Every session route is scoped by workspace and project as every product endpoint is; every
connector route takes `me` for the credential's project (`EPIC-043` `R-043-9`). Refusals use the
platform's error envelope; connector refusals are exactly `EPIC-043`'s.

## 1. Session routes — the Constraints screen (`FR-EXT-021`, `FR-EXT-040`, `FR-EXT-051`, `FR-EXT-065`)

| Route | Grant | Body / query | Returns |
|---|---|---|---|
| `GET /v1/projects/{id}/constraints` | member | `?kind=&status=` | `[{ id, kind, title, body, order, version, status }]` |
| `POST /v1/projects/{id}/constraints` | owner | `{ kind, title, body, order? }` | `201` the entry |
| `PATCH /v1/projects/{id}/constraints/{cid}` | owner | `{ title?, body?, order? }` | the entry, `version + 1` |
| `POST /v1/projects/{id}/constraints/{cid}/retire` | owner | — | the entry, `status: retired` |
| `GET /v1/projects/{id}/policy` | member | — | `{ oneSpecPerEpic, taskCeiling, splitRequiresConfirmation, offlineMode, version }` (defaults created on first read) |
| `PUT /v1/projects/{id}/policy` | owner | the four fields | the policy, `version + 1` |
| `GET /v1/projects/{id}/constitution` | member | — | `{ version, digest, renderedAt, content, inputs }` — renders when no render matches the current inputs |

Validation: `kind ∈ principle|constraint|non_goal`; `title` 1–120 chars; `body` ≤ 20 000 chars;
`taskCeiling` 1–500; `offlineMode ∈ strict|provisional`. A title equal to a reserved heading
(*Governed Execution*, *Decomposition Policy*, *Steering*) is accepted and rendered under its
kind; the preview notes it (Edge Cases).

## 3. Session read for the screens (`FR-EXT-067`)

`GET /v1/projects/{id}/workstation-connections` (`EPIC-043`) rows gain `constitutionDigest`,
`constitutionState`, `constitutionReportedAt` and — since Phase 9 (`T1542`) —
`constitutionRenderVersion`: the version of the render the reported digest is, resolved on the
read; null for `drift`, `missing` and an unreported file. The project screen and the Constraints
screen show *file differs* while any connection's latest state is `drift` or `stale`, naming the
render version whose digest it last matched (`stale` → *matches render v<n>*) or *no render*
(`drift`).

## 4. The rendered constitution (`FR-EXT-020`, `FR-EXT-022`, `FR-EXT-023`, `FR-EXT-027`)

Exact shape; `\n` endings; trailing newline; the digest is SHA-256 of these bytes.

```markdown
<!-- GENERATED by PMI Studio from project <projectId> · constitution version <n> · digest <sha256>
     Do not edit here. Change constraints in PMI Studio → Governance → Constraints, then run
     /setup-PMIStudio or any governed command to refresh. -->

# <Project name> Constitution

## Core Principles

### <title>            ← one per active kind=principle, by order
<body>

## Constraints

### <title>            ← kind=constraint

## Non-goals

### <title>            ← kind=non_goal

## Decomposition Policy

- One specification per Epic.                                   ← when oneSpecPerEpic
- An Epic whose task estimate exceeds <taskCeiling> MUST be split before /speckit-tasks; a split
  is proposed by the agent and confirmed by a human.             ← when splitRequiresConfirmation
- Policy version <version>.

## Governed Execution

Offline mode: <strict|provisional>

<invariant text — owned by PMI Studio, exported by @pmi/workspace-bundle, byte-identical in every render>

## Steering

### <subject>          ← one per resolved steering document, broadest scope first
<content>
```

An empty section keeps its heading and one line `_None recorded._`. The header's *digest* is the
digest of the file **with the header's digest field replaced by 64 zeros** at hashing time, so the
file can carry its own digest; readers hash the same way.

## 5. The invariant Governed Execution text (`FR-EXT-020`)

Held in `packages/workspace-bundle/constitution/governed-execution.md`, exported by
`governedExecutionSection(offlineMode)`. Its intent, verbatim from PMI-DOC-007 §5.4: every
governed command in this project MUST be registered with PMI Studio before it starts and completed
after it ends, through the `pmi-studio` tools; never write to PMI Studio's database; never approve
your own proposed status transition; if PMI Studio is unreachable, stop and say so (strict mode)
unless the project's offline mode permits provisional records, which are not governed until PMI
Studio reconciles them. The conformance test compares every render's section to this file
byte-for-byte (`SC-EXT-009`).
