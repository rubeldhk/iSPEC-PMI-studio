# DEF-029-003 — the shell's own buttons were never restyled, so a delivered page mixes two visual languages

**Originating task**: T885 (found while driving the keyboard pass against the running application)
**Found**: 2026-08-22
**Status**: OPEN — disposition belongs to T904 triage

## Reproduction

Sign in, open any project. The page renders the restyled `PageHeader`, `FormField`, `Select` and
`Button` components — and, between them, two controls straight from `frontend/src/main.tsx` that
carry no design-system class at all:

- the **Traceability** button, which stretches the full width of the viewport as a plain
  browser-default button;
- the **Back to project** button on the traceability view.

## Expected vs actual

Expected (`US2`: *"a user moves between screens without encountering different button shapes"*;
`SC-DS-003`): every visual value on a delivered surface resolves to a token. Actual: two buttons
on the project surface render in browser-default styling and are visibly not the same product.

## Why every check passed anyway

`FR-DS-050` enumerates *"the four delivered pages and two components"* and `main.tsx` is named in
neither — it was treated as the shell, not as a page. The lint rule (`T878`) cannot see this
either: an **absence** of styling contains no literal visual value, so a bare `<button>` is
perfectly legal to it. `T883`/`T894` render pages and components, never the shell's own markup.

The result is that the one file guaranteed to appear on every screen is the one file no restyle
task owned. This is the same shape as the finding that produced `T913`: the shell is where
"nobody's job" collects.

## Suggested remediation (not applied — T885 is a recording task)

Restyle the two shell controls onto `Button`, and consider whether `main.tsx`'s navigation should
become the inventory's `Navigation` component, which exists and is unused by any delivered page.
That is a task, not an edit: `/speckit-tasks` or a converge pass should raise it.
