# DEF-029-006 — the Traceability accessibility assertion covered a page half of which never rendered

**Originating task**: T883 (the page-level axe suite); found by `T926` during the Phase 9 run
**Found**: 2026-08-23, from an unhandled React error in an otherwise green `pnpm vitest` run
**Status**: RESOLVED (2026-08-23, `T926`)

## Reproduction

Run `pnpm vitest run --project frontend`. The suite reports **all tests passing** and, separately,
one unhandled error:

```text
Vitest caught 1 unhandled error during the test run.
TypeError: Cannot read properties of undefined (reading 'length')
 ❯ TraceabilityPage frontend/src/pages/Traceability.tsx:144:47
This error originated in "tests/unit/a11y/pages.spec.tsx"
The latest test that might've caused the error is "Traceability"
```

## Cause

`frontend/tests/unit/a11y/pages.spec.tsx` stubbed `getProjectCoverage` with an object of a shape
`CoverageReport` has never had:

```ts
getProjectCoverage: vi.fn(async () => ({
  totalRequirements: 1, coveredRequirements: 1, coveragePercent: 100, uncovered: [],
})),
```

The real contract (`frontend/src/services/api.ts`) is `uncoveredRequirementIds`,
`specificationsWithoutTasks`, `requirementCount`, `specificationCount`. So
`coverage.uncoveredRequirementIds.length` threw, React unmounted the coverage section, and **axe
scanned a Traceability page with no coverage section in it** — while `T883`'s assertion, which is
"zero violations", passed precisely because the markup it would have judged was never there.

The mock is cast `as unknown as ApiClient`, which is why `tsc` could not see it either. The cast is
load-bearing for the other page stubs, so the fix is the shape, not the cast.

## Why it matters more than one test

`T883` is the task that discharges `SC-DS-001` — *every delivered page passes the automated
accessibility check*. For one of the four delivered pages that claim was **partly vacuous**, and it
had been since the suite was written. This is the third variant in this Epic alone of the same
shape: a check that passes because the thing it checks was not there (`T537` anti-vacuity, `T886`
missing states, and now this).

## Resolution

`T926` replaced the stub with the real `CoverageReport` shape, carrying **non-empty** gap lists so
the coverage section renders its populated branch rather than its "None —" branch. The unhandled
error is gone from the run and axe now scans the whole page.

## Follow-up not taken here

A stronger fix would type the page stubs against `ApiClient` so the compiler rejects a wrong shape,
retiring the `as unknown as` cast across `pages.spec.tsx`. That touches every page stub in the
file and is not this Epic's to do — it is recorded here so the next Epic touching that file has the
reason in front of it.
