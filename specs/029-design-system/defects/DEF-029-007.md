# DEF-029-007 — the Tier 2 reachability evidence outlived the build it was evidence of

**Originating task**: T900a (the Constitution XI Tier 2 transcript); found while implementing Phase 9
**Found**: 2026-08-23
**Status**: PARTIALLY RESOLVED — SignIn and the shell re-driven 2026-08-23 (`T927`); Projects and
Requirements still stale, and belong to the same human session as `T885`

## Reproduction

`docs/accessibility/EPIC-029-reachability-transcript.md`, as committed on 2026-08-21, records:

```json
{"step":"signed in, Projects page rendered","resolved":{"bodyBackground":"rgb(255, 255, 255)"}}
```

Phase 9 moved the page onto `--color-canvas`. The body background is now `rgb(246, 247, 249)` in
light and `rgb(11, 17, 32)` in dark. **The transcript records a value the application no longer
produces**, and `T900b` — the check written specifically to keep that transcript honest — stayed
green throughout, because it tested that the file *was* evidence and never that it was evidence of
*this* build.

## Why it matters

Constitution XI Tier 2 is a closure gate, and `T901a` confirmed it. A gate confirmed against a
build that has since been restyled is not a gate; it is a date. Every previous instance of this
shape in the programme was caught by a person opening a browser after the Epic was declared done,
which is the exact failure Principle XI exists to prevent — so the principle's own evidence being
allowed to go stale is the sharpest possible version of it.

The trigger was not carelessness: Phase 9 was appended *after* `T901a` confirmed closure-readiness.
Nothing in the task list said that changing the visual layer invalidates the reachability run,
because until Phase 9 nothing had changed it afterwards.

## Resolution so far

- **`T927`** re-drove the run against the restyled build and appended the verbatim records: the
  Phase 9 shell renders (sticky `.ds-topbar`, `.ds-content`), the canvas token reaches the
  document in both themes, and there is **no horizontal overflow** at 1280×800 or 360×640, at
  100% or 200% text zoom, in either theme.
- **`T928`** closed the gap in the check itself. `tests/governance/reachability-transcript.spec.ts`
  now asserts the transcript contains the `--color-canvas` and `--color-surface` values
  `themes.css` currently declares, in both themes, and fails naming the token and telling the
  reader to re-run `T900a`. Mutation-verified against the literal miss above — a transcript saying
  `rgb(255, 255, 255)` against a canvas of `#f6f7f9`. **A hand cannot satisfy this check without
  running the application**, which is the property Tier 2 needs and did not have.

## What is still open

The **authenticated half**. Projects and Requirements need a signed-in session, and the agent
performing the Phase 9 run does not enter credentials into a running application. Those two pages
are precisely where the new Table tools bar, tinted StatusPill and PageHeader description render,
so they are the pages whose staleness matters most.

**Disposition**: it is `T927`'s open remainder, and it belongs with `T885` — the human performing
the manual keyboard and screen-reader pass is signed in on the restyled build already, and
re-driving two pages at 360×640 and 200% zoom in both themes is minutes of work on top of it.
Until it is done, Tier 2 is satisfied for SignIn and the shell and stale for the other two, and
`T901a` may not be re-confirmed.
